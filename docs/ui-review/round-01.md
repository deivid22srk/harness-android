## Importantes (P1)

1. **[AgentSession.kt:96,103,111,133,429 + 390-393]** `publish(ChatState(error = …))` substitui `internal` inteiro → **a transcrição inteira é apagada** quando o processo do Pi falha de forma persistente ou o handshake quebra após itens existirem. Impacto: usuário perde a visualização de toda a conversa no exato momento em que algo deu errado (o pior momento para perder contexto). Correção: publicar `internal.copy(error = …)` em vez de um estado novo; limpar `items` apenas em `newSession`/`hydrateMessages` intencional.
2. **[Composer.kt:216-227 + HarnessViewModel.kt:370 + AUDIT.md N2]** Não existe caminho de UI para enviar/steerar com o agente ocupado: o botão de enviar vira Stop e `steer()` é código morto; o rótulo "Na fila: N" (Composer.kt:122) nunca pode ser populado pela UI, embora o protocolo suporte (`sendPrompt` com `streamingBehavior: followUp`, AgentSession.kt:176). Impacto: usuários de apps de chat esperam enfileirar a próxima mensagem (ChatGPT/Gemini fazem isso); hoje é preciso esperar ou abortar. Correção: enquanto `busy`, botão secundário "Enfileirar" chamando `viewModel.steer(text)` (ou `send`, que já faz followUp) e limpar o draft após enfileirar.
3. **[HarnessViewModel.kt:379-383 vs 361-368]** `regenerate()` reenvia `sendPrompt(prompt)` **sem as imagens** da prompt original. Impacto: "Regenerar" após mensagem com anexo produz resposta sem o contexto visual, silenciosamente. Correção: guardar `lastImages` junto de `lastPrompt` e reenviar ambos.
4. **[AgentSession.kt:157-179]** `sendPrompt` não trata falha: `rpc?.call(...)` retorna `null` em timeout/sem conexão sem qualquer sinalização; a mensagem só existe localmente (`appendUserLocally:378-388`) e é descartada na próxima hidratação. Impacto: usuário "envia" e a mensagem some ou nunca é respondida, sem erro. Correção: checar retorno de `call` e emitir `SessionNotice(Error)` + marcar erro no estado.
5. **[Color.kt:21 vs UI + docs/DESIGN.md:12 + Color.kt:6-9]** `textTertiary` (#6B7488 escuro = 4,12:1; #8189A0 claro = 3,29:1) é usado como texto pequeno (12–14 sp) em MessageActions (ChatScreen.kt:517-524), nome do modelo (ChatScreen.kt:248-256), duração de tools (ToolCallCard.kt:131-133), status "cancelado" (ToolCallCard.kt:111-115) e `%` de contexto (Composer.kt:131-138) — falha WCAG AA (4,5:1). O DESIGN.md afirma validação por `scripts/contrast_check.py`, **script inexistente** em `scripts/`. Impacto: metadados ilegíveis para baixa visão; afirmação de qualidade falsa. Correção: escurecer/clarear o token (ex.: #8791A8 escuro ≥4,5 sobre #0B0E14; #6C7489 claro) e versionar o script de contraste no repo ou remover a alegação.
6. **[HProgressStep.kt:92-118]** `HProgressBar` sem `semantics { progressBarRangeInfo }`/`contentDescription`. Impacto: TalkBack não informa o progresso do provisionamento — tela crítica na primeira execução. Correção: `Modifier.semantics { progressBarRangeInfo = ProgressBarRangeInfo(progress, 0f..1f) }`.
7. **[SettingsScreen.kt:530-557]** Checkbox artesanal (Box 20 dp + Check) sem `Role.Checkbox`, sem `stateDescription`/`toggleable`. Impacto: TalkBack anuncia apenas "clicável"; estado selecionado é invisível. Correção: `Modifier.toggleable(value=option.selected, role=Role.Checkbox, onValueChange=…)`.
8. **[Composer.kt:79]** Rascunho "por projeto" não funciona: `rememberSaveable(key = draftKey)` sem `inputs` não reseta ao trocar de projeto (texto do projeto A aparece no projeto B) e só o último rascunho sobrevive à morte do processo. Impacto: risco de enviar um rascunho no contexto errado; contradiz DESIGN.md:99-100 e o doc do próprio Composer.kt:60. Correção: `rememberSaveable(stateSaver, inputs = arrayOf(draftKey))` ou holder por projeto.
9. **[ChatScreen.kt:119-122]** O texto real de `chat.error` (ex.: "Não foi possível iniciar o agente: …", "O agente não respondeu ao handshake") nunca é exibido — banner só mostra título genérico; `HErrorState` (que faria isso com diagnóstico) não é usado em tela nenhuma. Impacto: usuário não sabe o que falhou nem o que fazer além de "Tentar novamente". Correção: renderizar `sessionError` no banner (ou usar `HErrorState` com retry + diagnóstico).
10. **[HarnessViewModel.kt:300-311]** `openProject` sempre executa `session.start(config)` — voltar a Projetos e reabrir o **mesmo** projeto derruba e relança o agente (transcrição recarregada, segundos de espera). Impacto: navegação cotidiana custosa; streaming em curso é abortado. Correção: se `activeProject == project` e conexão `Connected`, apenas navegar; senão iniciar.
11. **[core: ProvisionState.kt:37-57; ChatState.kt:104-118; ChatReducer.kt:69-103; AgentSession.kt:96-133,424-436; SettingsRepository.kt:132]** Strings de usuário hardcoded em pt-BR fora de recursos, enquanto o app expõe `values-en`. Impacto: locale inglês recebe UI mista pt/en — o i18n anunciado no AUDIT N9 ("✔ todas as strings em recursos") não se sustenta. Correção: mover para recursos (via mapeamento no VM/UI por tipo de estado) ou retornar enums/IDs da camada core.
