## Importantes (P1)

1. **[i18n — core ainda fala português para usuários `values-en`]** O padrão "core language-neutral + UI localiza" foi aplicado só a tool labels/onboarding. Continuam hardcoded pt-BR e visíveis ao usuário: `AgentSession.kt:96,103,111,133,180,186,189,197,203,444-449,456` (erros do banner/notices — ex. "O agente não respondeu ao handshake (get_state)", "A mensagem não foi confirmada pelo agente (timeout)"); `ChatReducer.kt:69-103` (notices de compactação/retry que aparecem na transcrição) e `ChatReducer.kt:280-282` (cabeçalhos de diff "− antigo"/"+ novo" renderizados em `DiffView`); `Provisioner.kt:38-39,52,61,70,72,75,87,152,173` (mensagens que chegam como `ProvisionState.Failed.message` e são exibidas em `OnboardingScreen.kt:169`); `SettingsRepository.kt:132` (`keyHint = "chave do provedor"` — placeholder do campo de chave de provedores personalizados). Impacto: com locale inglês, o app exibe UI mista pt/en exatamente nos momentos de erro. Correção: estender o padrão já usado em `ToolCallCard` — core retorna tipos/enums e a UI mapeia para `stringResource`; para `ProvisionState.Failed` manter o detalhe técnico e traduzir o título/contexto.
2. **[a11y/contraste — 4 pares usados na UI falham AA no tema claro e o script não os cobre]** Cálculos (fórmula WCAG, mesma do script):
   - `toolOk` claro #059669 sobre `surface` #FFFFFF = **3,77:1** — usado como texto mono pequeno em "+N" (`ToolCallCard.kt:129`); sobre `codeBackground` #F1F3F9 = **3,40:1** — linhas adicionadas do diff (`ToolCallCard.kt:254`). A paleta já define `LightSuccessText` #067647 (5,69:1 em `strings` do script) mas `HarnessColors` **não tem slot `toolOkText`** e a UI usa `toolOk`.
   - `toolError` claro #DC2626 sobre `codeBackground` #F1F3F9 = **4,35:1** — linhas removidas do diff (`ToolCallCard.kt:255`).
   - `toolRunning` claro #B45309 sobre `toolRunningContainer` #FCEDD4 = **4,35:1** — texto do snackbar de aviso (HFeedback.kt:166-167; de fato emitido, ex. "O agente encerrou inesperadamente…", AgentSession.kt:454-459).
   Contradição direta da alegação "every text pair ≥ 4.5:1" (Color.kt:6-9, DESIGN.md:12-13): o script valida os pares que **listou**, não os que a **UI usa**. Correção: adicionar slots `toolOkText`/`toolErrorText` claros (#067647 / #B42318) e usá-los em texto pequeno; estender `contrast_check.py` com os pares diff/código e snackbar-warning (idealmente derivando os pares dos tokens).
3. **[UX — "Editar e reenviar" não edita]** `ChatScreen.kt:454` expõe a ação com rótulo `msg_edit_resend` ("Editar e reenviar"), que chama `onEditResend(item.text)` → `ChatScreen.kt:133` → `viewModel.send(text)`: reenvia o texto original **imediatamente**, sem oportunidade de edição. Impacto: ação enganosa — o usuário espera o composer preenchido e dispara um envio duplicado sem querer. Correção: preencher o draft do composer com `item.text`, focar o campo e não enviar; ou renomear a ação para "Reenviar".
4. **[UX/robustez — rascunho por projeto é só "reset", não "por projeto"]** `Composer.kt:80-81`: trocar de projeto apaga o rascunho anterior sem possibilidade de recuperação (não há holder por projeto), e após morte do processo o último rascunho é restaurado sob o **primeiro projeto aberto** (rascunho do projeto A pode aparecer no projeto B). O comentário do código (`Composer.kt:60,80` — "per project, survives process death… restores its own") e `DESIGN.md:99-100` afirmam o contrário do que o código faz. Correção: `SaveableStateHolder`/`rememberSaveable` com chave composta por projeto + persistir `activeProject` (ou mover o draft para o VM, persistido por `hostPath`).
5. **[Performance — jank de streaming não tratado]** Sem alteração desde a rodada 01 e sem correção alegada: (a) `parseInline` (`HMarkdown.kt:151`) e `highlightCode` (`HCodeBlock.kt:105`) fazem `text.substring(idx)` por iteração — O(n²) por parágrafo/bloco, re-executados a cada frame de streaming (o `remember(text)` só evita re-parse quando o texto **não** mudou — e ele muda a cada delta); (b) `ChatState` sem `@Immutable` (ChatState.kt:84) e `HarnessUiState` emitido 2× por publicação (`copy(chat=…)` + `refreshChatModels`, HarnessViewModel.kt:144-147) impedem skipping em ~30 fps; (c) `MutableInteractionSource()` criado por invocação (HCommon.kt:29) reinicia o ripple durante o toque quando o pai recomputa. Correção: tokenizar sem `substring` (índices), `@Immutable`/`@Stable` nos modelos de estado, consolidar a emissão em uma única cópia, `remember { MutableInteractionSource() }` no call site ou parâmetro opcional.
